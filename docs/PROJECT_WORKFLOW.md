# DropIn Project Workflow

## Purpose

This document defines how the product is designed and built.

The goal is to reduce unnecessary redesign, minimize decision fatigue, and ensure each screen reaches a high quality before moving on.

---

## Core Rule

Only one major goal is worked on at a time.

Do not begin designing the next screen until the current screen has been approved.

---

## Design Process

Each screen follows exactly the same process.

1. Information Architecture (IA)

   Define the structure and information hierarchy.

   ↓

2. Low-Fidelity Design

   Validate layout, spacing and interaction.

   ↓

3. Review

   Review with the product team.

   ↓

4. High-Fidelity Design

   Apply visual language, typography, colour, icons and motion.

   ↓

5. Review

   Iterate until approved.

   ↓

6. Production Build

   Move the approved design into the production application.

---

## Screen Order

The project will be completed in the following order.

1. Homepage
2. Results Page
3. Activity Detail
4. Map View

Do not skip ahead.

---

## Preview Environment

All design explorations live under:

`/design`

Examples:

- `/design/homepage-lowfi`
- `/design/homepage-highfi`
- `/design/results-lowfi`
- ...

These routes are temporary review environments.

Production pages should only be updated after approval.

---

## Review Philosophy

One Goal.

One Prompt.

One Review.

Each prompt should solve one problem only.

Avoid introducing unrelated ideas or future features unless requested.

---

## Product Principles

Always follow the Product & Design Principles.

Do not redesign previously approved product decisions unless explicitly requested.
